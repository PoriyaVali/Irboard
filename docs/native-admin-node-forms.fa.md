# فرم بومی نودهای پنل

فرم افزودن و ویرایش ۱۵ پروتکل جدید از React، DVA، Drawer و کنترل‌های Ant Design
موجود در Umi استفاده می‌کند. عرض، عنوان، ردیف‌های فرم و دکمه‌های ثابت پایین
همان الگوی ویرایشگرهای اصلی پنل هستند؛ در موبایل پنجره تمام عرض باز می‌شود.
گزینه‌های پیشرفته با دکمهٔ همان پنل باز می‌شوند. استفاده از JSON فقط برای
فیلدهایی است که مقدار واقعی آن‌ها آرایه یا شیء است، مانند peers و headers؛
تنظیمات عادی، فیلد مجزا دارند.

برای ۱۰ پروتکل اصلی نیز راهنمای فارسی و انگلیسی کنار فیلدها و در زیرصفحه‌های
TLS، DNS، قوانین و رمزگذاری قرار گرفته است. هر راهنما به کنترل مربوط از طریق
aria-describedby متصل است. خروجی فقط‌خواندنی دستور نصب V2node هم توضیح دارد.

پیش‌فرض‌های فرم جدید از کاتالوگ محافظت‌شدهٔ ادمین می‌آیند. ضریب مصرف ۱، نمایش
در اشتراک خاموش، پورت مناسب پروتکل و اعتبارسنجی گواهی روشن است. HTTP و SOCKS5
با TLS روشن شروع می‌شوند. برای شش پروتکل دارای سرور Mihomo، مدیریت با V2bX
به‌صورت پیش‌فرض روشن است: HTTP، SOCKS5، Mieru، ShadowQUIC، Sudoku و Snell. حالت
مدیریت و قابلیت واقعی هر پروتکل در خود فرم توضیح داده می‌شود؛ صرف حضور در
فهرست به معنای پیاده‌سازی سرور آن در V2bX نیست.

## نود مدیریت‌شده با V2bX

برای نودی که V2bX اجرا می‌کند فقط نام، گروه، آدرس و پورت اتصال لازم است:

- توضیح بالای فرم و راهنمای بخش‌ها به‌جای «هماهنگی با سرویس مقصد» می‌گویند که
  V2bX همین تنظیمات را روی سرور و در اشتراک کاربران اعمال می‌کند.
- پورت شنود سرویس اختیاری است؛ خالی یعنی همان پورت اتصال. فقط پشت NAT یا
  انتقال پورت عدد دیگری بنویسید. پیش‌فرض ۴۴۳ برای آن حذف شد، چون با تغییر فقط
  پورت اتصال، V2bX روی پورتی گوش می‌داد که کلاینتی به آن وصل نمی‌شد.
- مشخصات ورود هر کاربر و کلید Sudoku خودکار ساخته می‌شوند و زیر «تنظیمات
  پیشرفته» قرار دارند.
- پس از ثبت نود جدید، پنجره‌ای ID نود و قدم‌های بعدی را نشان می‌دهد: اجرای
  `v2bx config` روی سرور با همین ID (V2bX پروتکل و هسته را خودش تشخیص می‌دهد)،
  آبی شدن وضعیت نود و سپس روشن کردن نمایش در اشتراک.
- وضعیت نود از گزارش خود V2bX می‌آید: اگر V2bX نود را اجرا نکند (مثلاً پورت
  اشغال است یا گواهی گرفته نمی‌شود) وضعیت قرمز و مشکل زیر نام نود نمایش داده
  می‌شود؛ اگر اجرا کند ولی مشکلی داشته باشد، زرد.

دامنه، نام کاربری، کلید، شناسهٔ شبکه و اطلاعات گواهی از نمونه‌ها کپی نمی‌شوند.
ادمین باید مقدار سرویس واقعی را وارد کند. حساب‌های مدیریت‌شده می‌توانند خالی
یا دارای قالب {{uuid}} باشند تا اطلاعات هر کاربر جدا ساخته شود. پیش‌فرض‌ها
هنگام ویرایش دوباره اعمال نمی‌شوند؛ false، null و تنظیمات قبلی حفظ می‌شوند.
نود والد فقط از همان پروتکل انتخاب می‌شود و وراثت در فرم توضیح داده می‌شود.

## نگهداری

این مخزن bundleهای آمادهٔ پنل را نگه می‌دارد و پروژهٔ اصلی npm رابط کاربری
همراه آن نیست. منبع افزودنی‌ها و تولیدکننده‌ها به‌صورت مجزا نگهداری می‌شوند:

- `scripts/admin_mihomo_form.js`: فرم بومی ۱۵ پروتکل جدید.
- `app/Protocols/Mihomo/AdminForm.php`: متن، گروه‌بندی و پیش‌فرض‌های کاتالوگ ادمین.
- `scripts/admin_native_node_help.js`: راهنمای React فرم‌های اصلی.
- `scripts/patch_admin_mihomo_nodes.py` و `scripts/patch_admin_native_node_help.py`:
  تولید بخش‌های مشخص‌شده در هر دو bundle، با حفظ کدهای خارج از همان بخش‌ها.

پس از تغییر منبع:

```sh
python3 scripts/patch_admin_mihomo_nodes.py
python3 scripts/patch_admin_native_node_help.py
python3 scripts/patch_admin_mihomo_nodes.py --check
python3 scripts/patch_admin_native_node_help.py --check
node --test tests/AdminMihomoNodesBrowserTest.cjs
vendor/bin/phpunit --no-coverage --filter 'AdminFormMetadataTest|MihomoNodesTest|MihomoSubscriptionTest'
```

اگر متادیتای PHP عوض شود، fixture مرورگر باید از
`AdminForm::catalog(Outbound::catalog())` دوباره تولید شود. تست PHP تطابق دقیق
fixture و کاتالوگ، پیش‌فرض‌های بدون اطلاعات ساختگی و سازگاری مقادیر انتخابی
با validator واقعی پروتکل را بررسی می‌کند. متادیتا فقط در API ادمین است و به
سابسکریپشن کاربران یا تنظیمات runtime سرور افزوده نمی‌شود.
